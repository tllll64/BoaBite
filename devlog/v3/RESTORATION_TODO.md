## 13. 分批执行与验收方式

推荐顺序：**A 素材基线 → B 首页 → C 相机确认 → D 投喂结果 → G 异常 → 真实能力与全流程回归**。

每批只对齐一个页面或一组紧密关联状态。页面内部先完成比例、布局、素材和文案，再补动态与数据；不能用静态整屏图替代可操作页面。

| 批次 | 首次对齐目标 | 依赖 | 状态 |
|---|---|---|---|
| A | 素材联系表与映射 | 原始素材 | 待开始 |
| B1 | 未投喂首页 | A | 待开始 |
| B2 | 少量 / 大量投喂首页及透视 | B1、状态 fixture | 待开始 |
| C1 | 相机静态与操作 | A | 待开始 |
| C2 | 食物确认与纠错 | C1 | 待开始 |
| D1 | 投食状 | C2 | 待开始 |
| D2 | 加载与结果 | D1 | 待开始 |
| E | 日记两种面板状态 | — | 本轮不做 |
| F | 三种装扮与切换 | — | 本轮不做 |
| G | 异常路径 | 主流程 | 待开始 |
| FINAL | 完整回归与交付核对 | 所有批次 | 待开始 |

每次交付须包含：本次任务 ID、参考 PDF 页 / 视频时间点、相同状态下的网页截图、预览地址、已知差异、待用户对齐项。**工程完成**和**用户视觉验收通过**分别记录；未经用户确认不得宣称“完全还原”。
